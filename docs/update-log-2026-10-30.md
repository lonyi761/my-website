## 3. 資安第 1 步：資料庫權限（已生效）

**問題**：資料庫沒有權限控管，任何人不登入就能讀取全部成員、帳號 email，也可能修改或刪除資料；任何註冊者都能把自己升成總管理員。

**已在 Supabase 執行**（`supabase/security-step1.sql`）：
- 6 張資料表全部開啟 RLS，並建立 24 條權限規則；清除 2 條舊的「全部允許」規則。
- 帳號保護：一般帳號只能改自己的顯示名稱；角色、到期日、停權狀態、幫會權限只有總管理員能改。
- 共用職能、共用技能（不屬於任何幫會者）所有登入者可讀。

**現在的權限**：

| 資料 | 誰能看 | 誰能改 |
|---|---|---|
| 帳號 | 自己；總管理員看全部 | 自己只能改顯示名稱；其餘限總管理員 |
| 幫會 | 有查看權 | 改名：有編輯權；新增／刪除：總管理員 |
| 成員、聯賽、排表 | 有該幫會查看權 | 有該幫會編輯權 |
| 共用職能、技能 | 所有登入者 | 任何幫會的編輯者 |
| 未登入的人 | 什麼都看不到 | 不能做任何事 |

**驗證結果**：

| 測試 | 結果 |
|---|---|
| 未登入讀取 6 張表 | 全部 0 筆 |
| 未登入新增資料 | 拒絕（401） |
| 總管理員（你的帳號） | 成員 241 人、聯賽、排表、職能、技能、控制台 11 個帳號皆正常 |
| 模擬幫主帳號 | 只看到自己 2 個幫會（165 人、10 場聯賽），可編輯 75 人 |
| 模擬一般幫眾 | 看到 2 個幫會（166 人、15 場聯賽、57 筆職能），可編輯 0 人 |
| 一般幫眾嘗試自升總管理員 | 拒絕，資料未變 |

## 4. 資安第 2 步：停權、到期、刪除帳號（資料庫已生效）

**問題**：停權沒有任何作用；試用到期只在按登入時檢查；刪除帳號後對方再登入會被自動重建並重送 7 天試用。

**已在 Supabase 執行**（`supabase/security-step2.sql`）：
- 被**停權**或**試用到期**的帳號，資料庫一律視為沒有任何權限（總管理員不受到期限制）。
- 新增「刪除帳號」資料庫函式：只有總管理員能用、不能刪自己，會刪除登入帳號本身。

**驗證結果**（測試在交易中進行並自動回復，沒有改動任何人的資料）：

| 同一個一般幫眾帳號 | 成員 | 聯賽 | 職能 | 技能 |
|---|---|---|---|---|
| 正常 | 166 | 15 | 57 | 42 |
| 停權後 | 0 | 0 | 0 | 0 |
| 到期後 | 0 | 0 | 0 | 0 |
| 嘗試刪除別人的帳號 | 拒絕：「只有總管理員可以刪除帳號」 | | | |

## 5. 網頁調整（PR #2，待合併）

| 頁面 | 改動 |
|---|---|
| 登入 | 停權、到期、已刪除的帳號登入時直接說明原因並登出；**不再自動重建已刪除的帳號** |
| 登入 | 註冊帳號 ID 只能用英文、數字、底線，輸入中文會提示（過去含其他字元註冊的舊帳號仍可正常登入） |

| 總管理員控制台 | 改角色、停權前會確認；不能變更／停權／刪除自己；刪除帳號改為真正刪除（對方無法再登入）；失敗會提示 |
| 成員 | 「新增幫會」「刪除幫會」只有總管理員看得到；幫會齒輪只有有編輯權的人看得到 |

| 成員 | 移除截圖導入中寫死的測試假名單 |
| 聯賽 | 沒有編輯權的人看不到「編輯／刪除」，也不能點比賽結果與對陣幫會；建立與複製只列出可編輯的幫會；失敗會提示 |
