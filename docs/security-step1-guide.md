## 開啟後的權限

| 資料 | 誰能看 | 誰能新增／修改／刪除 |
|---|---|---|
| 帳號（profiles） | 自己；總管理員看全部 | 自己只能改顯示名稱；其餘限總管理員 |
| 幫會 | 有該幫會查看權 | 改名：有編輯權；新增／刪除：總管理員 |
| 成員、聯賽排表 | 有該幫會查看權 | 有該幫會編輯權（自己新增的成員也可改） |
| 幫會專屬職能、技能 | 有該幫會查看權 | 有該幫會編輯權 |
| 共用職能、技能（不屬於任何幫會） | 所有登入者 | 任何幫會的編輯者 |
| **未登入的人** | **什麼都看不到** | 不能做任何事 |

> 行為變化：只有「查看權」的人，之後**不能**再改聯賽結果、對手、排表（以前網頁沒擋）。

## 執行步驟（約 15 分鐘，請用電腦）

**建議先合併 PR，等 Vercel 部署完成（約 1 分鐘）再執行 SQL。**

1. 打開 [Supabase 後台](https://supabase.com/dashboard) → 你的專案 → 左側 **SQL Editor** → **New query**。
2. 打開 repo 裡的 `supabase/security-step1.sql`。
3. **第 0 段（檢查）**：只貼上第 0 段兩個 `select` 執行。把結果截圖給我，我確認沒有我不知道的資料表。
4. **第 1 段**：貼上執行。應顯示 `Success`。此時網站沒有任何變化。
5. **第 2 段**：貼上執行。應顯示 `Success`。網站仍然沒有變化。
6. **第 3 段**：**一次只執行一行**，每執行一行就到網站確認：

   | 執行 | 到網站確認 |
   |---|---|
   | `profiles` | 登出再登入；右上角帳號、授權幫會正常；總管理員控制台看得到所有人 |
   | `guilds` | 成員頁左側幫會清單正常 |
   | `guild_members` | 成員列表、人數正常；新增一位測試成員再刪除 |
   | `guild_rosters` | 聯賽列表正常；打開一場排表 |
   | `preparation_roles` | 戰備 → 職能管理正常 |
   | `preparation_skills` | 戰備 → 技能管理正常 |

7. 全部完成後告訴我，我會用未登入的方式再測一次，確認外部已經讀不到資料。

## 出問題時

- 某頁讀不到資料：到 SQL 檔最下方「緊急還原」，對那張表執行對應的 `disable row level security` 一行，就會立刻恢復原狀，再把畫面截圖給我。
- 執行時出現紅字錯誤：整段截圖給我，不要繼續往下執行。
- 執行過程中網站會短暫維持舊行為，不會遺失任何資料；SQL 不會刪除或修改任何成員、排表資料。
